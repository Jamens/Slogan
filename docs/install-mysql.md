# 在本机装上 MySQL 并连上

搭家把图纸直接写进本机 MySQL(8.x)。这份说明是**验收 6 的一半** ——「一台未装 MySQL 的机器上打开本应用,能得到下一步该做什么的可读指引」。

> 这一页是**人工验收**,不是自动判据:照着它能不能装上,得你自己走一遍。应用里的「一键复制诊断」会把当前错误码与文案原样带出来,对着下面四节查最快。

## 装 MySQL 8

Windows 上最省事的是官方安装包(MSI)。要点只有三条:

1. **开发机端口默认 3306**,除非你装的时候改了。搭家的连接向导默认填 `127.0.0.1:3306`。
2. **认证插件**:MySQL 8 默认 `caching_sha2_password`。如果你的驱动握不上手(见下面「认证失败」),装的时候可以选 `mysql_native_password`。**新装的库建议留着默认** —— 那是长期方向。
3. **记住 root 口令**:向导第一次填的就是它。装完忘了只能重置,流程在 MySQL 手册里。

装完确认服务在跑(默认服务名 `MySQL80`):

```bash
# 服务没起来的话,MySQL 服务状态查询
sc query MySQL80
```

## 四种连不上的情形

向导里点「测试连接」,按屏幕上的那一行标题对到下面对应的一节。

### 连不上这个地址

先确认服务已经启动,再确认主机名和端口填的是同一台机器上那一套。

> 屏幕上的下一步:先确认服务已经启动，再确认主机名和端口填的是同一台机器上那一套。

具体查法:

- 服务没起 ⇒ 用上面的 `sc query MySQL80` 看状态;是 `STOPPED` 就去服务面板启动它。
- 主机名填了 `localhost` 但 MySQL 只监听 `127.0.0.1` ⇒ 改成 `127.0.0.1`。
- 端口填错 ⇒ `netstat -ano | findstr 3306` 看谁在听。

### 认证失败

用户名或口令不对，也可能是服务端的认证插件不被驱动支持。

> 屏幕上的下一步:按安装说明的「认证失败」一节三步排查：用户名、口令、认证插件。

三步排查:

1. **用户名**:默认是 `root`。如果你在安装时改过管理员账号,用那个。
2. **口令**:注意大小写与首尾空格 —— 向导里的口令**首尾空白会被拒**(那通常意味着你粘贴时多带了一个空格)。
3. **认证插件**:在 MySQL 里跑 `SELECT user, host, plugin FROM mysql.user;`。看到 `caching_sha2_password` 而你的驱动握不上手 ⇒ 那就是这一层,把插件改成 `mysql_native_password`,或换个新一点的驱动。

### 库不存在

连上了服务器，但那个库还没建。

> 屏幕上的下一步:按安装说明的「库不存在」一节建库建表，`pnpm db:sql` 可以导出建表语句。

**这一步不用你手工做**:打开工程列表那一发会自动建库并跑迁移(`ensureSchema`)。所以看到这一行,点「保存配置」然后进工程列表就行。

如果它反复出现 ⇒ 迁移没跑成,看 `docs/install-mysql.md` 同目录的应用日志里 `migrate` 那一段。

### 连上了又被断开

端口能连上，但对面说的话不像 MySQL。

> 屏幕上的下一步:先看 3306 端口被哪个程序占用；不是 MySQL 就改端口，是 MySQL 就是服务中途重启了。

先看 3306 端口被哪个程序占用:

```bash
netstat -ano | findstr 3306
```

- 占用的**不是** MySQL ⇒ 把向导里的端口改成那个程序实际用的端口。
- 占用的是 MySQL,但你刚才**改过它的端口** ⇒ 旧端口上可能是别的程序。
- 占用的是 MySQL 且端口没改 ⇒ 那多半是服务中途重启了,重试一次。

### 连不上但超时

连不上也没被拒绝，一直到超时。

> 屏幕上的下一步:先改用 127.0.0.1 试一次；还不行就去看安装说明「连不上但超时」一节的防火墙那一头。

先改用 `127.0.0.1` 试一次 —— 这一格最常见的原因是**主机名解析走了网络**:填了机器名或局域网 IP 时,系统要先做一次名字解析,而那一步本身可能就卡在防火墙后面。

还不行 ⇒ 看防火墙那一头:Windows Defender 防火墙默认拦未列入允许列表的入站连接,而 MySQL 的 3306 是入站端口。装 MySQL 时它通常会自己加一条允许规则;如果你后来禁用过防火墙,那条规则可能已经没了。

## 连上之后

保存配置，然后在工程列表里新建或打开一个工程。

- 列表空 ⇒ 点「新建」建一个工程(它会建库、跑迁移、写第一层楼)。
- 列表里有一行但打不开、且名字眼熟 ⇒ 可能是上一次建工程时进程被杀,留下了一个只有工程行的残骸(**S1 没有删除入口**)。要清掉它得手进 MySQL:`DELETE FROM dajia.project WHERE name = '那个名字';` —— 别删整个库。

口令存在**本机用户目录**下(加密,只有这台机器的当前 Windows 用户能解)。换机器或换 Windows 用户之后读不出来是**正常**的,重填一次即可。

## 一键复制诊断

点「一键复制诊断」把原文贴出来查，或按原文里的错误码搜索。

卡住时点它,把那段文字贴出来查 —— 里面带**驱动给的原始错误码**(比如 `ECONNREFUSED`、`ER_BAD_DB_ERROR`),那是唯一能精确定位的信息。应用不会改写它。
